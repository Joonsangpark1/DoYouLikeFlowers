# 2026-09-24 — observe/actuate 아키텍처 논의: SmolVLA + HIL-SERL 하이브리드 고려

## 1. observe/actuate를 나누는 게 맞는가?

**결론: 분리 유지가 맞음.**

이유: 두 문제가 서로 다른 시간축/데이터 요구를 가짐.
- observe: pick 한 번당 한 번 도는 느린 고수준 판단("뭘 어디서 집을지")
- actuate(HIL-SERL): 10Hz로 도는 저수준 제어 루프

이걸 하나의 end-to-end 정책(RT-1/RT-2류, 이미지→행동 직접 매핑)으로 합치는 대안도 있지만,
"빨간 장미" 같은 언어 개념을 처음부터 학습시키려면 웹 스케일 사전학습이 필요해 비현실적이라고 처음엔 판단함.
→ 이 판단은 아래 3번에서 일부 수정됨 (파인튜닝 vs 처음부터 학습은 다른 문제).

트레이드오프: observe→actuate 좌표 핸드오프(observe의 위치 오차가 HIL-SERL이 학습한 접근 반경 안에 들어와야 함)를
잘 설계해야 함 — 각 모듈 PLAN.md에 "미정" 항목으로 이미 기록돼 있음.

## 2. "소규모 데이터"의 구체적 기준

| 규모 | 데이터양 | 할 수 있는 것 |
|---|---|---|
| HIL-SERL | 데모 15~30개 + 온라인 RL 상호작용(수십 분~수 시간) | 고정된 태스크 하나 |
| 단일 태스크 모방학습(ACT, Diffusion Policy) | 데모 50~200개 | 고정 태스크 하나, 정밀도는 HIL-SERL보다 보통 낮음 |
| RT-1 (로봇 데이터만) | 13대 로봇, 17개월, 13만 에피소드, 700+ 태스크 | 여러 태스크, 로봇/액션 공간은 고정 |
| RT-2 / OpenVLA류 (오픈보캐뷸러리) | RT-1급 로봇 데이터 + 웹 스케일 이미지-텍스트 수십억 쌍 사전학습 | 처음 보는 조합의 텍스트 지시도 이해 |

핵심 기준은 데이터 개수 자체가 아니라 **일반화 범위**. 태스크가 고정이면 수십 개 데모로 충분(HIL-SERL이
이 용도로 설계됨). "장미"/"빨간색" 같은 언어 개념 자체를 배우려면 웹 스케일 사전학습이 필요 — 단,
이건 **처음부터 학습**할 때 얘기고, **이미 사전학습된 모델을 파인튜닝**하는 건 완전히 다른 얘기임 (3번 참고).

## 3. 파인튜닝 재검토 → SmolVLA 발견

로컬 `~/lerobot`에 이미 구현돼 있는 걸 확인함 (`docs/source/smolvla.mdx`, `src/lerobot/policies/smolvla/`).

**SmolVLA 스펙:**
- Hugging Face의 450M 파라미터 경량 VLA (`lerobot/smolvla_base`)
- 입력: 카메라 이미지 + 로봇 상태 + **자연어 지시문** ("pick the red rose") → 행동(action chunk) 출력
- **파인튜닝 전제 모델** — 자체 데이터로 파인튜닝 필요, 권장 데이터량 **태스크당 데모 ~50개**
  (공식 예시: 큐브 위치 5곳 × 10개 = 50개. 25개로는 부족했다고 공식 문서에 명시)
- 파인튜닝: A100 1장 4시간, 또는 무료 Colab 노트북
- **참조 하드웨어가 SO-100/SO-101** — 우리 로봇 그대로

→ "웹 스케일 사전학습이 필요해 비현실적"이라는 2번 결론은 **파인튜닝에는 적용되지 않음**.
이미 사전학습된 체크포인트를 가져와 HIL-SERL과 비슷한 데이터 규모(~50개)로 얹으면 됨.

## 4. 하이브리드 아키텍처 제안

```
frontend 레시피 → NL 지시문 생성("pick the red rose")
  → SmolVLA(파인튜닝) 실행: 넓은 시야로 탐색 + 대략 접근
    → [핸드오프 지점]
      → HIL-SERL(flower_pick) 실행: 마지막 수 cm 정밀 grasp
      → HIL-SERL(flower_place) 실행: 꽃병 슬롯에 정밀 삽입
```

- observe가 하던 "종류/색상 인식 + 대략 위치"를 SmolVLA가 이미지+지시문만으로 흡수 가능
  → 별도 YOLO 탐지기/카메라 캘리브레이션이 아예 불필요해질 수도 있음
- SmolVLA는 순수 모방학습(사람 개입 교정 루프 없음) → 정밀도 필요한 grasp/insert는 HIL-SERL이 여전히 담당

## 5. 고민지점 (설계 확정 전에 짚어야 할 것)

1. **핸드오프 경계 트리거**: SmolVLA가 언제 멈추고 HIL-SERL이 이어받을지 (거리 임계값? 스텝 수? 시야 내 크기?)
2. **액션 공간 불일치 가능성**: SmolVLA 출력과 HIL-SERL의 EE-delta 액션 공간이 같은 좌표계/단위인지 확인 필요,
   다르면 변환 레이어 추가
3. **HIL-SERL 학습 범위가 SmolVLA의 도착 지점 변동성을 커버해야 함**: HIL-SERL은 `lerobot-find-joint-limits`로
   고정된 좁은 workspace bound 안에서 학습됨. SmolVLA의 실제 도착 오차/분산을 먼저 측정한 뒤 그 범위를
   커버하도록 HIL-SERL 데모를 수집해야 함 — **순서가 중요, SmolVLA 먼저 측정 → HIL-SERL 범위 결정**
4. **지시문 템플릿 고정**: SmolVLA는 데모 수집 때 쓴 지시문 문구 분포에 맞춰 언어를 이해함. frontend가
   자동 생성할 문장이 데모 수집 템플릿과 달라지면 인식률 저하 가능 → 템플릿을 먼저 확정하고 그 템플릿으로만
   데모 수집
5. **카메라 구성 차이**: SmolVLA는 트레이 전체를 보는 넓은 시야, HIL-SERL은 좁게 crop한 시야가 보통 필요 —
   카메라 하나 공유 vs 두 개(고정 광각 + 손목 근접) 여부를 초기에 결정해야 리그를 다시 안 만듦
6. **observe를 완전히 없앨지, 가벼운 안전망으로 남길지**: SmolVLA가 엉뚱한 꽃을 집으려 하거나 핸드오프 지점이
   실제 꽃 근처가 아닐 수 있음 → "observe 완전 제거"보다 "무거운 탐지기 → 가벼운 검증 단계"로 축소하는 게
   더 현실적일 수 있음
7. **디버깅용 로깅**: 실패 원인이 (a)SmolVLA 오탐 (b)SmolVLA 부정확 동작 (c)핸드오프 타이밍 (d)HIL-SERL grasp
   실패 중 어디인지 구분 가능하도록 핸드오프 시점 영상/좌표를 항상 로깅하는 규칙을 처음부터 설정
8. **컴퓨팅 자원**: SmolVLA 파인튜닝에 GPU 필요(A100 기준 4시간) — 로컬 CUDA GPU 유무 확인, 없으면 Colab

## 6. 선행지식 우선순위

1. **VLA 모델 구조 감**: 비전 인코더+언어 인코더+action chunk 출력 head 결합 방식, action chunking 개념
   (SmolVLA·ACT 공통 핵심 아이디어)
2. **계층적/residual 제어 개념**: "coarse policy가 서브골까지 데려다주고 fine policy가 이어받는다"는 패턴
   (hierarchical RL, residual RL) — 고민지점 1~3번의 이론적 배경
3. **액션 공간/좌표계 변환 실무**: EE-delta vs joint space, 절대좌표 vs 상대좌표 (기존 FK/IK 선행지식과 연결)
4. **LeRobotDataset의 언어(task) 필드 스키마**: 데모 저장 시 지시문이 어디에 기록되는지 실무적으로 알아야 함
5. **단계별 평가 설계**: end-to-end 성공률만이 아니라 "SmolVLA 도착 성공률"과 "HIL-SERL grasp 성공률"을
   분리해서 로깅/평가하는 습관

## 8. SmolVLA 파인튜닝 실전 절차 (Colab 기준)

전체 흐름: `[로컬] 데모 수집 → HF Hub 업로드` → `[Colab/GPU] 파인튜닝 → 결과 모델 Hub 업로드` → `[로컬] 실제 로봇 실행`

**1단계 — 로컬 데모 수집**
```bash
hf auth login --token ${HUGGINGFACE_TOKEN} --add-to-git-credential
HF_USER=$(hf auth whoami | awk -F': *' 'NR==1 {print $2}')

lerobot-record \
    --robot.type=so101_follower \
    --robot.port=/dev/tty.usbmodemXXXX \
    --robot.id=my_follower_arm \
    --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 1920, height: 1080, fps: 30}}" \
    --teleop.type=so101_leader \
    --teleop.port=/dev/tty.usbmodemYYYY \
    --teleop.id=my_leader_arm \
    --dataset.repo_id=${HF_USER}/flower_pick_v1 \
    --dataset.num_episodes=50 \
    --dataset.single_task="pick the red rose"
```
`--dataset.single_task`가 곧 "지시문 템플릿"(5번 고민지점 4). 여기 적은 문구가 파인튜닝 후 SmolVLA가
이해하는 언어 그대로이므로, 태스크 변형(종/색/위치)마다 이 문구를 일관된 템플릿으로 바꿔가며 수집.

**2단계 — Colab에서 파인튜닝**
공식 노트북: `colab.research.google.com/github/huggingface/notebooks/blob/main/lerobot/training-smolvla.ipynb`
```bash
lerobot-train \
  --policy.path=lerobot/smolvla_base \
  --dataset.repo_id=${HF_USER}/flower_pick_v1 \
  --batch_size=64 \
  --steps=20000 \
  --output_dir=outputs/train/my_smolvla \
  --job_name=my_smolvla_training \
  --policy.device=cuda \
  --wandb.enable=true \
  --policy.repo_id=${HF_USER}/smolvla_flower_v1
```
- 무료 Colab GPU는 T4(16GB) — 문서 기준 A100 4시간은 안 맞음, batch_size 낮춰야 함
- 세션 끊김 대비: `--save_checkpoint_to_hub=true` 켜두면 `--config_path=${HF_USER}/smolvla_flower_v1 --resume=true`로 재개 가능
- 대안: Hugging Face Jobs(종량제, `--job.target=a10g-small`) — 세션 끊김 문제 없음

**3단계 — 로컬에서 실행**
```bash
lerobot-rollout \
  --strategy.type=base \
  --robot.type=so101_follower \
  --robot.port=/dev/tty.usbmodemXXXX \
  --robot.cameras="{ front: {type: opencv, index_or_path: 0, width: 640, height: 480, fps: 30}}" \
  --task="pick the red rose" \
  --policy.path=${HF_USER}/smolvla_flower_v1
```
`--task`도 데모 수집 때 쓴 `single_task` 문구와 최대한 동일하게.

## 9. 원격 컴퓨팅 구성 — 집 데스크탑(Windows, RTX 4060)을 HIL-SERL learner로

HIL-SERL은 GPU 자체는 안 무거움(SAC + ResNet10, `hilserl.mdx`에 `device: "cpu"`가 기본값으로 명시될 정도)
— 문제는 actor(로봇 옆, 실시간 제어)와 learner(GPU, gradient update)가 분리 가능한 구조인가였는데,
코드 확인 결과 가능함:
- `lerobot/policies/gaussian_actor/configuration_gaussian_actor.py`의 `ActorLearnerConfig`에
  `learner_host`(기본 "127.0.0.1"), `learner_port`(기본 50051) 필드 존재
- `lerobot/rl/learner.py`에서 `server.add_insecure_port(f"{host}:{port}")`로 바인딩 — 즉 같은 config 파일을
  양쪽에 복사해서 쓰면 learner는 그 주소로 바인딩, actor는 그 주소로 접속하는 식으로 동작
- 가중치 동기화가 4초 주기(`policy_parameters_push_frequency`)라 어느 정도 네트워크 지연 허용됨
  (매 액션마다 네트워크 타는 구조가 아님 — 실시간 제어는 actor 로컬에서 자체 처리)

**구성:**
```
[로봇 옆 로컬 머신]              [집 데스크탑 Windows+RTX 4060]
SO-101 + 카메라                  HIL-SERL learner (상시 실행)
  actor 프로세스   ──Tailscale──  SmolVLA 파인튜닝도 여기서 가능
```

**설정 절차:**
1. 절전모드 끄기 (설정→전원→절전 "안 함", USB selective suspend도 끄기) — 원격으로 깨울 수 없으니 필수
2. 양쪽에 Tailscale 설치(`tailscale up`) — 공유기 포트포워딩/DDNS 불필요, CGNAT 환경에서도 동작
3. Windows에 OpenSSH 서버 활성화:
   ```powershell
   Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
   Start-Service sshd
   Set-Service -Name sshd -StartupType Automatic
   ```
4. config의 `learner_host`를 데스크탑의 Tailscale IP로 설정, 양쪽에 같은 config 사용
5. 원격에서 `tmux`로 감싸서 실행 (SSH 끊겨도 유지):
   ```bash
   tmux new -s hilserl_learner
   python -m lerobot.rl.learner --config_path=...
   # Ctrl+B, D로 detach
   ```
6. 확인: `ssh 사용자@<tailscale-ip> "nvidia-smi"`

**GPU/OS 세부사항 (RTX 4060, 8GB, Windows):**
- WSL2(Ubuntu)로 충분 — 네이티브 Linux 듀얼부팅 불필요, 최근 WSL2 CUDA 패스스루 안정적
- **흔한 실수**: WSL2 안에서 NVIDIA 드라이버를 또 설치하면 안 됨 — 드라이버는 Windows 호스트 것 그대로,
  WSL2 안에는 CUDA 툴킷만 설치
- SmolVLA 파인튜닝(450M): 8GB면 `--batch_size=64`는 안 됨, `8~16` 정도로 낮추고 mixed precision 권장 —
  **Colab 결제 전에 로컬 4060으로 먼저 시도해보고, OOM 나면 그때 Colab/HF Jobs로 이동**하는 순서 추천
- HIL-SERL(SAC+ResNet10)은 4060으로 전혀 문제없음

## 11. 전시회향 스코프 조정

- **일반화보다 좁은 범위의 확실한 성공**: 방문객 자유 배치보다, 검증된 꽃 위치/조합 몇 가지에 데이터 수집을
  집중해서 그 범위 안 성공률을 최대화. frontend는 자유도는 유지하되 검증된 프리셋을 유도하는 UX 고려
- **실패 안전장치**: 자동 재시도 로직 최소 1회, 스태프가 기술지식 없이 리셋 가능한 절차, 성공 실행 영상 백업
- **현장 재캘리브레이션 버퍼**: 카메라-로봇 캘리브레이션은 조명에 민감 — 일정에 전시 전날/당일 재보정 시간
  필수로 확보, 가능하면 조명 통제용 장비(램프/조명박스) 지참
